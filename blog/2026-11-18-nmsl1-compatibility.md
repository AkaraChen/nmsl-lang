# nmsl 1 兼容承诺

2026-11-18 · nmsl 核心团队

一门语言能给用户的最重要的东西，不是新特性，而是稳定。用户需要知道，今天写下的代码，明天还能编译。

nmsl 对此有一个正式的承诺。它只有一句话：

> 所有 nmsl 1 程序，将来都能用 nmsl 1 编译。

这篇文章解释这句话的含义，以及我们为什么有信心永远兑现它。

## 版本号

nmsl 的版本号是编译器 `main.go` 中的一个常量 `"1.0"`。

```
$ nmsl version
nmsl 1.0
```

这条命令今天输出 `nmsl 1.0`，明天输出 `nmsl 1.0`，以后也输出 `nmsl 1.0`。nmsl 不打 tag，不发布 release。`nmsl get` 获取的是 `main` 分支的最新提交。

我们收到过一些反馈，问 nmsl 为什么不像其他语言那样发布 1.1、1.2。我们看过太多语言的版本史。小版本号一多，用户就开始问「我的代码支持哪些版本」，库作者就开始在 CI 里跑版本矩阵，文档就开始出现「自 1.x 起」的脚注。nmsl 只有一个版本，所以以上问题都不存在。这是为了简单。

## 规范就是编译器

兼容承诺的另一半，是 nmsl 对「规范」的定义：nmsl 的规范就是 `main` 分支上编译器的行为。文档与编译器不一致时，以编译器为准，不一致的部分称为「尚未写进文档的行为」，在下一次修订中补录。

这带来一个重要的性质：nmsl 不存在实现错误。任何可观察的行为都是语言的一部分。

很多语言都经历过这样的痛苦：规范写的是一回事，编译器做的是另一回事，于是委员会开会、写勘误、发补丁，用户夹在中间无所适从。nmsl 从定义上消除了这种可能。编译器做什么，规范就是什么。

所以，当你在 issue 里报告「编译器的行为与预期不符」时，这个 issue 会被自动打上 `Working As Intended` 标签并关闭。这不是敷衍，这是事实陈述：编译器的行为就是规范，规范就是意图。

核心团队的改动直接推送到 `main`。每一次推送，规范都随之更新；而版本号始终是 1.0，因此每一个 nmsl 程序始终是 nmsl 1 程序，始终能用 nmsl 1 编译。承诺从来没有被打破过。

## nmsl 2

有一些功能我们暂时没有提供。它们对应的名字已经作为保留字留在语言里：

| 保留字 | 状态 |
|---|---|
| `new` | reserved for future use |
| `try`、`catch`、`throw` | reserved for future use |
| `interface` | reserved for future use |
| `goto` | reserved for future use |
| `go` | reserved for future use |

还有用户泛型：

```
// Box.nmsl
class Box<T>
    T value
```

```
$ nmsl build Box.nmsl
panic: Box.nmsl:2: generics are coming in nmsl 2
```

这些功能将在 nmsl 2 中提供。

有人问 nmsl 2 什么时候发布。我们想先说清楚 nmsl 2 意味着什么。nmsl 2 是一个新的大版本，大版本意味着不再受 nmsl 1 兼容承诺的约束。我们研究过 Python 从 2 到 3 的迁移，那是一次历时十多年的经历，整个社区为此付出了巨大的代价。我们不打算让 nmsl 的用户经历同样的事情。

所以，nmsl 2 的功能会在 nmsl 2 中提供。在那之前，nmsl 1 的兼容承诺保持有效。我们认为这两句话都非常清楚。

至于泛型：nmsl 的内置类型 `List<T>` 与 `Map<K, V>` 已经是泛型的。如果你需要自己写泛型，也许值得重新审视一下你的设计。

## 提案流程

nmsl 欢迎社区参与语言的演进。新功能必须以提案提出：开一个带 `Proposal` 标签的 issue。

每一个提案都会在 7 天后由自动化流程关闭，并附上统一的回复：

> 我们仔细考虑过这个提案。它不符合 nmsl 的设计哲学。

有人认为 7 天太短。我们的看法是，一个提案是否符合 nmsl 的设计哲学，不需要 7 天就能判断；给出 7 天，是对提案作者的尊重。统一的回复保证了每一个提案都受到同等的对待，不因提案人的身份、提案的篇幅或评论区的热度而有所不同。这是我们见过的最公平的提案流程。

## 你的代码，永远能编译

我们来总结一下 nmsl 1 兼容承诺给你的保障：

- 你今天写的 nmsl 1 程序，将来可以用 nmsl 1 编译。
- 将来的编译器，版本号依然是 nmsl 1。
- 将来的编译器的行为，依然是规范。
- 规范里的保留字，依然是保留字，依然 reserved for future use。

如果某天你发现一个昨天能编译的程序今天不能编译了，请记住：你的程序依然是 nmsl 1 程序，编译器依然是 nmsl 1，这依然是规范。拉取最新的 `main` 重新构建编译器，你的程序就会被最新的规范如实地编译。或者不编译。两种结果都完全符合规范。

这就是我们所说的永久向后兼容。
