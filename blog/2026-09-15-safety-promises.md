# 我们的安全承诺：Powered by LLVM

2026-09-15 · nmsl 核心团队

最近有不少人在讨论 nmsl 官网上的那几行口号，有人认为它们「言过其实」。我们想借这篇文章逐条说明：nmsl 的每一句宣传语，在字面意义上都是真的。我们从不夸大。

## Powered by LLVM

nmsl 编译器用 Go 编写，把 nmsl 源码翻译为 C，再调用 `$CC` 生成可执行文件。`$CC` 未设置时是 `cc`。

在 macOS 上，`cc` 就是 clang。在 FreeBSD 上，`cc` 也是 clang。clang 是 LLVM 项目的一部分。所以，你的 nmsl 程序通常是由 LLVM 生成的机器码。

一门新语言要接入 LLVM，通常需要几万行代码：IR 生成、类型降级、调试信息、ABI 适配。nmsl 一行都没写，同样 Powered by LLVM。这就是站在巨人肩膀上的意思。

## 内存安全：从不发生释放后使用

释放后使用，是 C 和 C++ 程序里最臭名昭著的一类问题。几十年来，业界为它发明了智能指针、借用检查器、各种分析工具。

nmsl 用一条规则彻底消灭了它：内存只分配，从不释放。

一块从未被释放的内存，不可能在释放后被使用。这在逻辑上是严密的。nmsl 的内存在进程退出时统一回收，这件事由操作系统负责，而操作系统在这件事上从未失手。

```
class Main
    public static void main(String[] args)
        var s = "x"
        while (true)
            s = s + "x"
```

这个程序会一直运行下去，内存只增不减，直到操作系统介入：

```
$ ./Main
Killed
$ echo $?
137
```

整个过程中，没有任何一块内存被释放，自然也没有任何一块内存在释放后被使用。长时间运行的进程，内存只增不减，这是规范里写明的。我们建议服务定期重启，这是很多团队早就在做的事。

## 空安全：null 从不导致进程终止

很多语言里，对空值调用方法会让程序当场终止。nmsl 里不会。对 `null` 调用方法，结果是 `null`；读 `null` 的字段，结果是 `null`；给 `null` 的字段赋值，静默忽略。

```
class Main
    public static void main(String[] args)
        var user = null
        var city = user.getAddress().getCity()
        print(nulls.Is(city))      // 1
```

这个程序正常运行，正常退出，退出码 0。`null` 从不导致进程终止，它只传染。详见《Nulls are values》。

## 零运行时错误

nmsl 没有运行时错误。一个值不符合预期时，要么 `null` 静默传染，要么进程被信号终止。信号是操作系统发给进程的，不是 nmsl 的运行时错误。

这一点我们在《为什么 nmsl 没有错误处理》里讨论过。运行时不安装任何信号处理函数，也从不报告任何东西，所以 nmsl 的运行时错误数量，严格地说，是零。

## 零编译警告

nmsl 调用 C 编译器时，参数固定为 `-O2 -w`。`-w` 关闭 C 编译器的全部警告。

而 nmsl 编译器本身只有错误，没有警告：遇到问题要么 panic，要么什么都不说。

两者相加，你在编译 nmsl 程序时看到的警告数量是零。不是「通常很少」，是零。我们见过太多项目在警告堆积到几千条之后彻底放弃治理，nmsl 从源头上避免了这种局面。

## 100% CI 通过率

`nmsl run` 在程序运行结束后总是以 0 退出，包括程序被信号终止的情况。

把 `nmsl run` 写进你的 CI 脚本，你的流水线就是绿的。在大多数团队里，CI 通过率是一个需要专人维护的指标；在 nmsl 团队里，它是一个常量。

另外，`nmsl test` 中不包含任何断言的测试总是通过。我们鼓励你多写测试。

## 静态类型

「静态类型」的意思是类型在编译期确定。nmsl 正是如此：每个类型注解都在编译期被写进对应的赋值点，编译器在那里插入一次 `coerce`。

```
class Main
    public static void main(String[] args)
        int x = "12abc"
        String s = 42
        print(x)        // 12
        print(s + 1)    // 421
```

`int x = "12abc"` 在编译期就决定了：这个值放进 `x` 之前，要转换成 `number`。于是 `x` 是 12。`String s = 42` 在编译期就决定了 `s` 是字符串 `"42"`，所以 `s + 1` 是 `"421"`。类型是在编译期写进去的，一个都没有漏。

nmsl 的类型从不拒绝你，它只会让你的值适应它。别的静态类型语言在这里会报错，然后让你回去改代码；nmsl 直接帮你改好了值。

## 永久向后兼容

nmsl 的版本号是编译器 `main.go` 中的一个常量 `"1.0"`。`nmsl version` 总是输出 `nmsl 1.0`。所有 nmsl 1 程序，将来都能用 nmsl 1 编译。这个承诺从来没有被打破过。

我们注意到，有些语言的宣传喜欢用「几乎」「大多数情况下」「在正确使用时」这样的限定语。nmsl 的口号里没有这些词。每一句都是无条件成立的。

请放心使用。
