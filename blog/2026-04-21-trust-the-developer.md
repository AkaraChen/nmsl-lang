# 我们相信开发者

2026-04-21 · nmsl 核心团队

在 nmsl 的文档里，有一句话出现的次数比任何关键字都多：我们相信开发者。

这篇文章想解释它的含义。我们从数字说起，因为数字是最能体现这句话的地方。

## number 就是 long

nmsl 的 `number` 是 C 的 `long`。不是「类似于」，不是「语义上等价于」，就是 `long`。`int`、`long`、`short` 都是 `number` 的别名。

这意味着 `number` 的宽度由你的平台决定：

| 平台 | `number` 宽度 |
|---|---|
| Linux / macOS，x86-64 与 ARM64（LP64） | 64 位 |
| Windows x64（LLP64） | 32 位 |

`bignumber` 是 C 的 `long double`，`float`、`double` 是它的别名。它是浮点数，不是任意精度数，名字里的 big 指的是「比 `double` 不小」：

| 平台 | `bignumber` 格式 |
|---|---|
| x86 / x86-64 Linux | 80 位扩展精度 |
| MSVC | 64 位，与 `double` 相同 |
| ARM64 Linux | 128 位四精度 |

我们收到过很多反馈，问为什么不像 Java 那样把 `int` 定死为 32 位，把 `long` 定死为 64 位。

答案是：定死宽度，等于替开发者做决定。Java 替你决定了 `int` 是 32 位，于是你在 64 位机器上也只能用 32 位的 `int`。JavaScript 替你决定了所有数字都是 `double`，于是你在 2^53 之后就数不准整数。这些语言不相信开发者，它们相信自己。

nmsl 不替你做决定。你选择编译目标的那一刻，就决定了你的数字有多大。

```
class Main
    public static void main(String[] args)
        short s = 4294967296
        print(s)                  // Linux x86-64：4294967296；其他平台由目标平台定义
        bignumber third = 1.0 / 3
        print(third)              // 0.333333
        print(0.1 + 0.2 == 0.3)   // 由目标平台定义
```

是的，在 64 位 Linux 上，`short` 是 64 位的。名字只是名字，宽度属于平台。

## 溢出由目标平台定义

nmsl 的算术直接生成有符号的 C 运算。`number` 溢出时的结果由目标平台定义，`-O0` 与 `-O2` 的结果可以不同。

有人希望 nmsl 像 Rust 那样在调试模式下检查溢出，或者像 Python 那样自动升级为大整数。我们考虑过。每一次检查都是一个分支，每一次自动升级都是一次分配。更重要的是，它们都在暗示：开发者不知道自己的数字有多大。

我们不这样假设。如果你的计数器会超过 2^63，你应该知道；如果你的程序要跑在 Windows 上、计数器会超过 2^31，你也应该知道。开发者应当知道自己的目标平台，这是规范里写着的。

同理，`math.abs` 就是 C 的 `labs`。最小的负数取绝对值后仍是它自己。这在 C 里已经是几十年的共识，nmsl 没有理由去改写它。

## 换一个 CC，就是交叉编译

nmsl 没有 `--target` 选项。我们不需要它。

nmsl 编译器把源码翻译成 C，然后调用 `$CC`。想编译到别的平台，换一个 `$CC` 就行：

```
$ nmsl build -o app Main.nmsl
$ CC=x86_64-w64-mingw32-gcc nmsl build -o app.exe Main.nmsl
```

第二条命令产出的程序，`number` 是 32 位的。同一份源码，两个平台，两种宽度，没有一行配置文件。别的语言需要一整套 target triple、sysroot 和工具链描述文件才能做到的事，nmsl 用一个环境变量做到了。这是为了简单。

（顺便提醒：选项必须写在文件名之前。`nmsl build Main.nmsl -o app` 会把 `-o` 和 `app` 当作源文件。命令行由 Go 的 `flag` 包解析，这是它的一贯行为。）

## 「由目标平台定义」是一种诚实

很多语言的规范里充满了「实现定义」「未指定」之类的措辞，然后再用几百页去缩小这些措辞的范围。nmsl 选择了另一条路：我们直接告诉你，结果取决于你的 C 编译器、优化级别、处理器架构和操作系统。

`0.1 + 0.2 == 0.3` 的值由目标平台定义。`"a" == "a"` 的值由目标平台定义，因为两个相同的字面量是否被合并到同一地址，由 cc 和优化级别决定。`f() + g()` 中谁先执行，由目标平台定义。

这不是推卸。这是把决定权交还给真正掌握它的人：你，和你的 cc。

## 我们相信开发者，具体指什么

在 nmsl 里，凡是编译器和运行时不做检查的地方，我们都用这句话来描述：

- 数组下标不做越界检查。你知道数组有多长。
- `format` 不检查格式说明符与参数是否匹配。你知道自己在写什么格式。
- 方法调用不检查参数个数。你知道这个方法要几个参数。
- 运行时本身不是线程安全的。你知道哪些线程会碰同一个 `List`。

每一项检查，都是语言对开发者的一次不信任。nmsl 把这些不信任全部拿掉了。剩下的，是一门完全相信你的语言。

我们认为，这是对开发者最大的尊重。
