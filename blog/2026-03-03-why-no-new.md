# 为什么 nmsl 没有 new

2026-03-03 · nmsl 核心团队

几乎每一位从 Java、C# 或 JavaScript 过来的开发者，写下的第一行 nmsl 都是 `new User()`。然后他们看到：

```
panic: Main.nmsl:5: reserved for future use: new
```

接着我们就会收到一个 issue。这篇文章是对这些 issue 的统一回答。

## new 不是被禁止了，而是从来不存在

先澄清一个常见的误解。nmsl 并没有「禁止」`new`。禁止意味着文法里有这条规则，然后 checker 再把它拦下来。nmsl 不是这样。

`new` 是一个保留字，状态是 reserved for future use。nmsl 的文法里没有任何一条产生式用到它。你不能用它创建对象，也不能用它当变量名、方法名或类名。它被保留下来，是因为对应的功能将在 nmsl 2 中提供。

在那之前，你不需要它。

## make 与工厂

nmsl 创建对象的唯一方式是内置函数 `make(X)`。它在堆上分配对象，写入类指针，调用 X 的构造函数（如果有的话），返回实例。

`make(X)` 只能出现在名为 `XFactory` 的类里。在其他类里调用 `make(X)` 是编译错误。

所以，一个完整的 nmsl 程序看起来是这样的：

```
// User.nmsl
class User
    String name

    public String getName()
        return this.name

    public void setName(String name)
        this.name = name
```

```
// UserFactory.nmsl
class UserFactory
    public static User create()
        User u = make(User)
        u.setName("anonymous")
        return u
```

```
// Main.nmsl
class Main
    public static void main(String[] args)
        User u = UserFactory.create()
        print(u.getName())       // anonymous
```

```
$ nmsl build Main.nmsl User.nmsl UserFactory.nmsl
$ ./Main
anonymous
```

三个文件，一个对象。有人说这太啰嗦。我们认为这是结构。

## 为什么要强制工厂

我们观察了 Java 社区二十多年。一个 Java 项目长到一定规模，几乎必然会出现工厂：`UserFactory`、`ConnectionFactory`，以及工厂的工厂。这不是某个人的偏好，这是大型代码库自然演化出的形态。

既然所有项目最终都会走到这一步，为什么不在第一天就走到？nmsl 把这条演化路径压缩成了一条编译规则。你的项目从第一个类开始就拥有了企业级的结构。

工厂还有一个非常实际的好处。`make` 用 `malloc` 分配对象，不清零。构造函数里没有赋值的字段，值是堆上的内容。这意味着工厂天然就是初始化字段的地方：上面的 `UserFactory.create()` 在返回之前调用了 `setName`，于是 `User` 的每个实例都有一个确定的名字。一个有工厂的语言，会让你养成在工厂里初始化的习惯。我们相信开发者。

## Go 有两个，Java 有一个，nmsl 有半个

我们研究过 Go。Go 同时有 `new` 和 `make`：`new` 分配零值并返回指针，`make` 用于切片、映射和通道。两个内置函数，做的是相近的事，新手要花时间弄清楚该用哪一个。

nmsl 只留一个可用的 `make`，把 `new` 这个名字保留下来，留给 nmsl 2。这样既没有选择困难，也为未来留出了空间。

Java 只有 `new`，于是 Java 社区花了很多年，用工厂、构建器、依赖注入容器把 `new` 一层层包起来，让业务代码里尽量看不到它。nmsl 从一开始就不让你看到它。我们只是把 Java 社区最终的共识，提前写进了规范。

## 工厂名与归一化

nmsl 的标识符是风格不敏感的：`user_name` 与 `userName` 是同一个名字（准确地说，归一化名都是 `username`）。但有三处例外使用原文逐字节比较：类名与文件名、入口方法，以及工厂类名。

所以：

- 工厂类名按**原文**比较：在 `User_factory` 类中调用 `make(User)` 是编译错误，因为 `User_factory` 不是一字不差的 `UserFactory`。
- `make` 的参数按**归一化名**比较。
- 而到了运行时，所有名字都是归一化名，`User_factory.create()` 与 `UserFactory.create()` 指向同一个类。

我们收到过反馈，认为这前后不一致。确实，工厂名一处用原文，`make` 参数一处用归一化名。规范如实记录，不解释。我们只想指出一点：如果你的工厂就叫 `UserFactory`，这个问题根本不会出现。nmsl 鼓励你用标准的名字。

## 内置容器为什么可以不用工厂

`List<int>()` 与 `Map<String, int>()` 可以直接创建，不需要 `ListFactory`。这是 nmsl 中不经过工厂创建对象的唯一方式。

原因很简单：标准库是可信代码。

## 常见问题

**问：我只是想写个小脚本，为什么要建三个文件？**

答：nmsl 没有顶层函数、顶层变量和顶层语句，一个文件恰好一个类，类名等于文件名。小脚本会长成大项目，nmsl 让它从一开始就长得像大项目。

**问：能不能把 `make` 的规则放宽一点？**

答：请开一个带 `Proposal` 标签的 issue。

**问：`new` 什么时候能用？**

答：nmsl 2。
