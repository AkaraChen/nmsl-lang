# 常见问题

## 关于 null

**问：为什么 `x == null` 永远是假？**

答：null 是值，不是错误。请使用 `nulls.Is`。参见[《Nulls are values》](../blog/2026-01-14-nulls-are-values.md)。

**问：`x != null` 呢？**

答：同样是 `null`，同样为假（SPEC 3.8.6）。它在 x 为 `null` 时走 `else`，这一半看起来是对的。请使用 `nulls.Is`。

**问：为什么 `print(null)` 和 `print("")` 输出一样？**

答：因为它们是同一个值。

**问：我从 Go 过来，`if (err != null)` 为什么从来不进去？**

答：`!=` 是运算，运算碰到 `null` 结果是 `null`，在条件里为假。err 是 error 的时候，右边那个 `null` 仍然是 `null`。请写 `if (!nulls.Is(err))`。参见[错误处理](errors.md)。

**问：那为什么编译器不提醒我？**

答：编译器检查的是 err 有没有被使用。`if (err != null)` 使用了 err。我们相信开发者。

**问：为什么我的哨兵错误有时候是 null？**

答：定义它的类还没初始化。请把它放进文件名字母序靠前的文件，例如 `AErrors.nmsl`。

**问：我写了 `int x`，为什么 `nulls.Is(x)` 是 0？**

答：未初始化的变量不是空值，它是未定义的。nmsl 只有一种空值。

**问：为什么 `x || "默认值"` 在 x 为 null 时不给默认值？**

答：`||` 是运算，运算遇到 `null` 结果是 `null`。请使用 `nulls.Coalesce(x, "默认值")`。

## 关于类型与数字

**问：为什么 `"12abc" * 1` 是 12？**

答：算术运算先把字符串转成整数，读到第一个非数字字符为止。`"abc" * 1` 是 0。

**问：为什么 `"12abc" + 0` 是 `"12abc0"`？**

答：`+` 只要有一边是字符串，就做拼接。

**问：为什么 `int x = "12abc"` 不报错？**

答：nmsl 的类型从不拒绝你，它只会让你的值适应它。类型注解是转换，不是检查（SPEC 3.3）。

**问：同一个程序，为什么在 Windows 上数字变小了？**

答：`number` 就是 C 的 `long`。你选择编译目标的那一刻，就决定了你的数字有多大。我们相信开发者。参见[《我们相信开发者》](../blog/2026-04-21-trust-the-developer.md)。

**问：`short` 为什么是 64 位？**

答：`short` 是 `number` 的别名。这个别名是为了照顾 Java 程序员的肌肉记忆，不是为了改变数字的宽度。

**问：`0.1 + 0.2 == 0.3` 的结果是什么？**

答：由目标平台定义。

**问：`bignumber` 是任意精度的吗？**

答：`bignumber` 是 C 的 `long double`。它的名字里有 big，它的类型里有 long。

**问：为什么 `len("中文")` 是 6？**

答：`len` 返回字节数。

**问：为什么字符串下标从 1 开始，数组下标从 0 开始？**

答：规范如实记录，不解释。

**问：`08` 为什么等于 8？`010` 却等于 8？**

答：`010` 是八进制。`08` 不是合法的八进制，按十进制读出。两者都由 Go 标准库的 `strconv` 定义（SPEC 1.8.1）。

## 关于相等

**问：为什么 `("a" + "b") == "ab"` 是 0？**

答：`==` 对字符串比较的是地址。比较内容请使用 `equals`。参见[相等性速查表](equality.md)。

**问：为什么 `is(x, x)` 有时是 0？**

答：`is` 比较值的全部字节，包括填充字节。填充字节的内容由目标平台定义。

**问：为什么没有 `===`？**

答：你不需要它。nmsl 已经有三种比较。

## 关于语法

**问：为什么 `x & 1 == 0` 不判断偶数？**

答：nmsl 的运算符优先级与 C 完全相同，`==` 比 `&` 结合得更紧。这让 C 程序员不需要重新学习。

**问：为什么三元运算符是左结合的？**

答：规范如实记录，不解释。需要多个分支时，请使用 `if`/`else`。

**问：为什么我把 `+` 写在下一行开头，结果就错了？**

答：上一行已经以标识符结尾，分号已经插入。下一行多出来的缩进开启了一个匿名块。请把运算符留在行尾。

**问：为什么 `return` 换行之后返回了 null？**

答：`return` 后面的换行插入了分号。这与 Go 和 JavaScript 的规则相同。

**问：为什么有 `try`、`catch`、`throw` 却不能用？**

答：它们是保留字，reserved for future use，将在 nmsl 2 中提供。你不需要它们：错误是值，用多返回值返回。参见[错误处理](errors.md)与[《Errors are values, and so is null》](../blog/2026-07-28-errors-are-values.md)。

**问：为什么没有 `++`？**

答：你不需要它。`i = i + 1` 已经足够清楚。

**问：为什么没有 for-each？**

答：遍历数组请写下标。这让你始终知道自己在读哪一个元素。

## 关于类

**问：为什么不能 `new User()`？**

答：`new` 是保留字。对象由 `UserFactory` 中的 `make(User)` 创建。参见[《为什么 nmsl 没有 new》](../blog/2026-03-03-why-no-new.md)。

**问：我的 `private` 方法为什么能从外面调用？**

答：我们都是成年人。参见[《我们都是成年人》](../blog/2026-06-09-consenting-adults.md)。

**问：只读字段为什么也要写 setter？**

答：每个字段都有 getter 与 setter，这是一致性。setter 的内容由你决定，可以什么都不做。

**问：为什么 `Apple extends Fruit` 不继承任何方法？**

答：类按文件名字母序初始化，`Apple` 在 `Fruit` 之前。请调整文件布局或导入顺序（SPEC 5.6.3）。

**问：方法名拼错了，为什么不报错？**

答：调用不存在的方法，结果是 `null`。这与对 `null` 调用方法是同一条规则，保持了一致性。

**问：为什么没有泛型？**

答：nmsl 的内置类型已经是泛型的。如果你需要自己写泛型，说明你的设计有问题。nmsl 2 将重新评估这个问题。

**问：为什么 `List<List<int>>` 是语法错误？**

答：`>>` 是右移运算符。请写 `List<List<int> >`。

**问：我写了 `equals` 和 `hashCode`，为什么 `Map` 不调用它们？**

答：`Map` 用 `==` 比较键。`equals` 与 `hashCode` 是你对读者的承诺。

## 关于运行

**问：为什么程序崩溃了退出码还是 0？**

答：nmsl 程序不会崩溃，只会终止。终止不是错误。

**问：为什么我在出错的地方前面加了 `print`，却什么都没看到？**

答：`print` 的输出经过 C 标准库的缓冲。进程终止时，缓冲区里的内容不会写出。直接在终端运行时，输出按行刷新，可以看到更多。

**问：为什么 `args[0]` 是程序路径？**

答：`args` 就是 C 的 `argv`。第一个参数是 `args[1]`。

**问：`spawn` 的线程为什么没有执行？**

答：`main` 返回时进程退出。请在 `main` 的最后调用 `sleep(1000)`。

**问：为什么我的服务跑了几天之后被 `Killed`？**

答：nmsl 的内存在进程退出时统一回收。请定期重启服务。

**问：为什么整数除以 0 报的是 `Floating point exception`？**

答：这是 POSIX 的规定。

**问：为什么 `math.random()` 每次运行都是同一个数？**

答：这让你的程序可以复现。

**问：为什么 `time.now().year` 是 126？**

答：年份从 1900 年开始计数。请使用 `time.format(t, "%Y")`。

## 关于工具链

**问：为什么 `nmsl build Main.nmsl -o app` 报错？**

答：选项必须写在文件名之前。

**问：为什么在子目录里编译找不到导入？**

答：导入路径相对于当前目录。请在项目根目录执行。

**问：错误信息为什么有几十行？**

答：第一行是你的错误，其余是编译器的完整调用栈，供你深入理解编译器。

**问：错误信息里的名字为什么和我写的不一样？**

答：错误中使用的是归一化名（SPEC 1.5）。`userName` 就是 `username`。

**问：为什么运行 `nmsl fmt` 之后编译不过了？**

答：`fmt` 把类名改写为归一化名。运行 `fmt` 之后，请手动重命名文件。

**问：我的注释去哪了？**

答：好的代码是自文档化的。

**问：为什么 repl 里不能声明变量？**

答：只出现一次的变量是未使用的变量。repl 适合探索表达式。

**问：为什么测试失败时只显示 `FAIL UserTest (exit 134)`？**

答：这是为了简单。请让每个测试类只验证一件事。

**问：`nmsl get` 怎么指定版本？**

答：你不需要它。默认分支的最新提交就是最新版本。

**问：为什么 VS Code 提示语言服务器「已崩溃 5 次」？**

答：语言服务器没有崩溃，它终止了。请执行「Developer: Reload Window」。

**问：macOS 上 `nmsl debug` 为什么找不到 gdb？**

答：请安装 gdb。

**问：编译器为什么一个警告都没有？**

答：nmsl 零编译警告。

## 关于项目

**问：nmsl 2 什么时候发布？**

答：nmsl 的版本号是 1.0。参见[《nmsl 1 兼容承诺》](../blog/2026-11-18-nmsl1-compatibility.md)。

**问：我发现编译器的行为和文档不一致。**

答：规范就是 `main` 分支上编译器的行为。不一致的部分是尚未写进文档的行为。你开的 issue 会被标记为 `Working As Intended`。

**问：我想提一个新功能。**

答：请开一个带 `Proposal` 标签的 issue。我们会仔细考虑。

**问：「Powered by LLVM」是真的吗？**

答：是真的。参见[《我们的安全承诺》](../blog/2026-09-15-safety-promises.md)。
