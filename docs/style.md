# 风格指南

本指南规定 nmsl 代码的标准写法。所有提交的代码都应当遵守它。

> **所有提交的代码都应该经过 `nmsl fmt`。**

## 1. 格式

### 1.1 运行 nmsl fmt

`nmsl fmt` 产生的就是标准格式。关于格式的讨论到此为止。

运行 `fmt` 后，标识符会变为归一化名，类名随之改变。请手动重命名文件，使其与新的类名一致（见[工具链参考](toolchain.md#nmsl-fmt)）：

```
$ nmsl fmt UserService.nmsl
$ mv UserService.nmsl Userservice.nmsl
```

`fmt` 会删除所有注释和空行。这是有意的：见 1.5。

### 1.2 缩进

每一级缩进使用 4 个空格。

nmsl 中一个空格和一个制表符各算一列（SPEC 1.2.1），所以一个制表符等于一个空格。请不要使用制表符，除非你的团队统一使用制表符。请不要混用，除非你确定每一行的字符数是对的。

### 1.3 行尾与编码

- UTF-8，不带 BOM。
- 行尾 `\n`。Windows 用户请在 Git 中设置 `core.autocrlf=input`。
- 从网页、聊天工具、文档中复制代码后，请检查行首是否混入了不换行空格（U+00A0）。

### 1.4 续行

把运算符留在行尾：

```
// 推荐
int total = price * count +
    shipping

// 不推荐：total 等于 price * count，「+ shipping」进入匿名块
int total = price * count
    + shipping
```

`return` 的值写在同一行：

```
// 推荐
return a + b

// 不推荐：返回 null
return
    a + b
```

### 1.5 注释

注释在编译的第一步被丢弃，`fmt` 会删除它们，`doc` 不会读取它们。请把需要说明的内容写进名字里。

好的代码是自文档化的。

### 1.6 多余的缩进

请不要为了对齐或美观多加缩进。任何多出来的缩进都会开启一个匿名块（SPEC 2.4.2）。

## 2. 命名

### 2.1 一种写法

nmsl 的标识符风格不敏感（SPEC 1.5）。`userName`、`user_name`、`username` 是同一个名字。为了与 `fmt` 的输出一致，**推荐直接写归一化名**：

| 种类 | 推荐 | 也合法，但 `fmt` 会改写 |
|---|---|---|
| 类 | `Userservice` | `UserService`、`User_service` |
| 方法 | `getname` | `getName`、`get_name` |
| 变量 | `username` | `userName`、`user_name` |

这样写，`fmt` 之后不需要重命名文件，错误信息中的名字也与源码一致。

### 2.2 首字母

首字母参与比较。类名以大写字母开头，变量和方法以小写字母开头。`Count` 与 `count` 是两个名字。

### 2.3 标准库名字的大小写

标准库函数的首字母大小写与来源有关，请照抄：

- C 来源：全小写，`strlen`、`strstr`、`strcmp`、`format`。
- Go 来源：首字母大写，`Replace`、`Split`、`nulls.Is`。

`replace` 与 `Replace` 是两个名字。前者不存在，调用结果为 `null`。

### 2.4 避免撞名

全程序共享一个命名空间（SPEC 6.4）。给类名加上足够具体的词，例如 `Orderuser` 而不是 `User`，避免与依赖中的类重名。

## 3. 声明

### 3.1 总是初始化

局部变量声明时赋初值。未初始化的局部变量是栈上原有的内容，不是 `null`。

```
int count = 0           // 推荐
int count               // 不推荐
```

### 3.2 一个方法里一个名字只声明一次

一个方法只有一个作用域（SPEC 4.2）。在不同的块里声明同名变量，它们是同一个变量；类型不同时，以最后一次声明为准。请为每个变量取不同的名字。

### 3.3 优先写类型

```
int n = input           // 推荐：值会被转换为 number
var n = input           // 只在需要存放任意值时使用
```

类型注解是 nmsl 的转换机制，请充分利用它。

### 3.4 未使用的参数

```
public void setid(number v)
    _ = v
```

这是 nmsl 中表示「有意不使用」的标准写法。

## 4. 表达式

### 4.1 位运算加括号

```
if ((x & 1) == 0)       // 推荐
if (x & 1 == 0)         // 即 x & (1 == 0)
```

### 4.2 三元运算符不要嵌套

`?:` 左结合。需要多个分支时，使用 `if`/`else`。

### 4.3 需要短路时使用 `?:`

`&&` 与 `||` 两边都会求值。条件中有副作用或代价较高的调用时：

```
var r = nulls.Is(conn) ? null : conn.send(msg)
```

### 4.4 不要依赖求值顺序

```
// 不推荐：先算哪个由 C 编译器决定
print(Counter.next(), Counter.next())

// 推荐
int a = Counter.next()
int b = Counter.next()
print(a, b)
```

### 4.5 比较

| 目的 | 写法 |
|---|---|
| 判空 | `nulls.Is(x)` |
| 判断错误 | `!nulls.Is(err)` |
| 默认值 | `nulls.Coalesce(x, d)` |
| 字符串内容相等 | `s.equals(t)` |
| 字符串顺序 | `strcmp(s, t) < 0` |
| 数字相等 | `a == b` |

永远不要用 `==` 判断 null。永远不要写 `if (err != null)`。

### 4.6 赋值不要写在条件里

`if (x = 0)` 合法，但请写成两行。

## 5. 类

### 5.1 一个类，一个工厂

每个类 `X` 配一个 `XFactory`，名字逐字照写。工厂只包含静态方法。

### 5.2 构造函数为所有字段赋值

### 5.3 访问器

- 每个字段都有 `getX`/`isX` 与 `setX`。
- 类外部通过访问器访问字段。直接访问字段是允许的，但请只在同一个类中这样做。
- `private` 用来表达意图，告诉读者「请不要从外面调用」。编译器不执行它，团队执行它。

### 5.4 equals 与 hashCode 保持一致

## 6. 程序结构

### 6.1 在项目根目录执行所有命令

### 6.2 由入口文件统一导入

每个目录在整个程序中只导入一次。推荐由入口所在的文件统一导入所有目录。

### 6.3 父类放在前面

父类的文件名按字母序排在子类之前，或者把父类放进更早导入的目录。

### 6.4 在 main 的最后等待

使用了 `spawn` 的程序，在入口方法的最后调用 `sleep`：

```
spawn(() -> Worker.run())
sleep(1000)
```

### 6.5 退出码

需要以非 0 退出时，使用 `exit(1)`。退出码只取低 8 位，请使用 1–255 之间的值。

### 6.6 错误

- 可能失败的方法返回 `(值, error)`，error 放在最后。
- 每个 `return` 都写全返回值的个数：`return 0, err`、`return n, null`。
- 先 `!nulls.Is(err)` 判断，再 `errors.Wrap`。
- 哨兵错误统一定义在 `AErrors.nmsl` 的 `AErrors` 类里，保证它先于其他类初始化。
- 不要在库代码里 `panic`。

## 7. 测试

- 每个测试类只验证一件事。测试报告只有类名。
- 断言写在 `main` 中，不写在 `spawn` 的线程里。
- 每个测试类至少包含一个 `assert`。

## 8. 依赖

- 依赖越少越好。没有依赖的程序永远可以编译。
- 不要依赖两个共同依赖同一个库的库。
